# AGENTS.md — Rebuilding ripgrep (regex engine scope) from this spec

This spec was generated by the `regent-reverse` skill against the
`BurntSushi/ripgrep` Git repo at depth=1 (commit `227381d`, version
`ripgrep 15.2.0`).

## Scope (read this first)

**Scope = single-module (`crates/regex`).** The full repo is 101 `.rs` files
across a 9-crate workspace plus integration tests, fuzz targets, and CI.
This spec does **not** cover the CLI dispatcher (`crates/core/main.rs`),
the search driver (`crates/searcher`), or the ignore filters. See
`specs/_scope.md` for the skipped list.

Rebuilding **only** the regex engine requires implementing the
`grep_matcher::Matcher` trait for `regex_automata`. That is enough for the
spec to be self-contained; the rest of ripgrep can be reattached by reading
`specs/regex.spec.md` and the module map.

## Rebuilding instructions

1. Read `architecture.md` to understand the layer cake.
2. Read `specs/regex.spec.md` for MUST/SHOULD contracts.
3. Implement only what those specs require. The original `matcher.rs` is
   ~670 LOC and gives you most of the shape, but **do not transcribe** —
   specs are the contract, source is evidence.
4. After implementation, walk `inventory/functional-checklist.md` top-to-
   bottom. Each item is a `- [ ]` with a verification command. The rebuild
   is done when every item passes.

The spec does NOT carry full type signatures for `regex_automata::meta::Regex`
and friends — those come from upstream crates and are not part of ripgrep's
contract. Treat them as fixed external dependencies (see `dev-env.md`).
